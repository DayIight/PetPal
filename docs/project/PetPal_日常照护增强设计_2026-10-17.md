# PetPal 日常照护增强设计 · 2026-10-17

用户已选择本轮添加：1 快捷记录、2 搜索筛选、3 医疗资料夹、4 用药疗程、5 照护交接卡。账号和云同步独立于本轮。本轮沿用 iOS 16、SwiftUI、离线 Core Data，不增加服务端或外部依赖。

## 共同架构

新增 V4 Core Data 模型，以 `CDCareItem` 存储带类型的 JSON 载荷，包含 id、petID、category、payload、createdAt。四种类别为 quickAction、medicalDocument、medicationCourse、careInstructions，均从属于真实宠物。`CareItemStore` 统一读写，同现有记录、提醒共用 context 和保存回滚机制；附件放在现有媒体目录，用随机文件名标识。新资料纳入完整备份及宠物级联删除，旧模型/旧备份可轻量迁移。备份恢复校验载荷与宠物/媒体/提醒关联，失败保留原库。

## 1 快捷记录

「今日」显示当前宠物的常用快捷项，最多 6 项；可添加、命名和删除。复用同类最近记录的常用填写内容，生成新记录 ID 和当前发生时间，清除旧照片、完成提醒关联、下次计划等事件专属内容；打开现有表单核对后保存，取消不产生记录。不把复制操作视为已经完成健康事件。

## 2 搜索与筛选

「记录」支持搜索类型、模板名、字段值和备注，可叠加单一记录类型及含首尾整日的日期范围。始终限定当前宠物；有筛选时显示列表结果，显示无结果、清除筛选和非法日期范围提示。无筛选时保留现有时间轴/日历交互。

## 3 医疗资料夹

从「我的」进入当前宠物资料夹。支持 PDF/JPEG/PNG 导入，标题、资料日期、医院、备注，以及可选关联健康记录；可查看原件、编辑元信息、删除及分享。PDF 每份最多 20 MiB、200 页，不接收加密/无法读取文件；图片沿用 10 MiB、4096px/1600 万像素预算，导入时归一化，名称不作为磁盘路径。异步读取文件且持有系统安全访问权限；失败不保存元信息或残留文件，删除数据库成功后再清理文件。附件原件纳入备份，不进行 OCR 或自动解读。

## 4 用药疗程

从提醒管理进入疗程，填写药名、主人记录的单次用量/说明、起止日期和每日 1–6 个不重复时间，最长 180 个日历日。每个时间关联一条有起止范围的提醒规则，现有待办完成机制继续负责提交实际服药记录；提供明确的跳过记录，不建议补服或自动调整剂量。支持查看历史、编辑未来安排、暂停/恢复、结束和删除疗程；编辑保留未变时间的提醒身份，旧完成记录仍保留。疗程结束后不继续通知，跨日和 Widget 共用日期规则，有限排程明确显示截止日期。

## 5 照护交接卡

从「我的」进入，为当前宠物保存饮食安排、日常照护、注意事项和紧急联系人。导出前选择过敏信息、用药安排、兽医联系方式等内容，预览范围后分享 PDF。仅包含当前宠物，不默认附带芯片号、所有病历或医疗原件；长文本分页，失败显示错误。用药为主人填写的安排，不提供诊断或处方建议。

## 验证

新建/重启持久化、不同宠物隔离、复制草稿清除事件字段、搜索组合与日期边界、资料导入拒绝/清理、疗程起止/多时间/跳过/编辑/完成事务、交接卡内容与分页，以及 V3 迁移、完整备份往返与失败保留数据。完成单元与关键 UI 回归及 Release 无签名编译；真机通知和 Files/iCloud 文档供应商仍按发布验收记录实测。
